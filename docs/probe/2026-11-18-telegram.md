# 渠道探测记录：Telegram（2026-11-18）

环境：macOS 27.2.1 (26B131) / Apple Silicon / Telegram 13.1.0（`ru.keepcoder.Telegram`，原生 AppKit 版）
权限：辅助功能 ✓；屏幕录制 ✗（`screencapture -l` 报 could not create image）。

**本记录只含结构信息，不含任何聊天正文。**

## 1. 结论

| 能力 | 结论 | 依据 |
|---|---|---|
| 读消息 | **AX 不可读，必须走截图 OCR** | 消息列表 `AXList` 的 `AXChildren` 为 0；整窗只有 4 个 `AXStaticText`（标题栏/会话标题） |
| 定位输入框 | ✅ AX 可定位 | 底部 `AXTextArea`，可写 |
| 填入 | ✅ AX 写入可用 | `AXUIElementSetAttributeValue` 读回一致 |
| 发送 | ✅ AX 动作可用 | 有内容时出现 `AXButton("Send")`，actions = `AXPress`, `AXShowMenu`，enabled |

→ Telegram 的自动化不需要任何合成事件（CGEvent）：读走 OCR，写和发送都走 AX。这一点比微信安全得多。

## 2. AX 树实况

窗口 480×616 点，`AXWindows=1`（**Telegram 不在前台时读到 0**，切到前台后 1；HUD 本来就只在前台分析，不影响）。

整窗 DFS 只走到 27–28 个节点：

```
AXWindow
├─ AXList kids=0                      ← 消息列表：自定义绘制，不暴露子节点
├─ AXScrollBar (5 个 AXButton 子节点：上下翻页/翻行)
├─ AXButton "BotFather"               ← 会话标题（也是按钮）
├─ AXButton "Back" / "Search" / "More"
├─ AXButton "Send media" / "Open" / "Discard" / "Emoji" / "Voice message"
├─ AXStaticText len=18                ← 输入框上方的占位/提示文本
├─ AXTextArea len=18 writable=True    ← 消息输入框
├─ AXButton "Send"                    ← 仅当输入框有内容时出现（替换 Voice message）
└─ 关闭/最小化/全屏 + 标题栏文本
```

要点：

- **正文不在树里**。`AXList` 的 children 恒为 0，无论私聊还是群聊；这是 Telegram 的异步自绘列表，不实现 NSAccessibility 子节点。
- 输入框可写，但 **API 返回 `-25200`（kAXErrorFailure）而值其实写进去了**——必须以读回内容为准，不能看返回码。
- 发送按钮是标准 `AXButton`，`AXPress` 可用；按钮标题随界面语言变化（"Send"/"发送"…），**不能写死标签**。
- 非前台时 `AXWindows=0`：AX 读取必须发生在 Telegram 前台时（HUD 的既有前提）。

## 3. 对实现的影响

1. `src/apps/telegram_app.py`：读消息走 `CaptureApp(profile)` + OCR（复用微信截图路径），**不是** `ax_app.py` 那种 AX 解析。
2. 输入框/发送用新的通用 `src/ax_input.py`（按 pid + 窗口矩形找 AXTextArea / AXButton），`AXPress` 发送。
3. 窗口尺寸门槛要按 app 配：Telegram 当前窗口 480 宽，微信路径的 `w>=500` 门槛会把它漏掉。
4. 需要屏幕录制权限才能实机校准；AX 部分现在就能验。

## 4. 实测：AXPress 发送（2026-11-18 19:20，收藏夹 / Saved Messages）

- 写入：`AXUIElementSetAttributeValue(textarea, AXValue, "测试：jev-jarvis 无障碍发送 …")` → 读回一致（API 返回 -25200，但值已写入）。
- 发送：找到 `AXButton("Send")`，`AXUIElementPerformAction(btn, AXPress)` 返回 0；1.2s 后输入框内容为空（Telegram 发送成功即清空输入框）。
- 全程零 CGEvent 合成事件，未触碰剪贴板。

结论：**Telegram 的自动填写 + 自动发送可以完全走 AX**，风险等级远低于微信。
